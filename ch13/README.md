# ch13 — 기권을 걷어내기 (13부)

11부는 기권을 도입해 신뢰도를 올렸습니다. 13부는 반대로 **이미 과하게 기권하는
시스템에서 기권을 안전하게 걷어냅니다.**

## 가상 데이터입니다

`corpus_tax.py` 의 세무 문서는 **전부 지어낸 것**입니다. 가상 회사의 사내 안내라는
설정이고 조항·금액·기한이 실제 세법과 무관합니다. **실제 세무 판단에 쓰지 마세요.**

여기서 재려는 것은 세법이 아니라 **"답이 문서 안에 있는지 없는지를 시스템이
구분하는가"**입니다. 문서를 저자가 썼기 때문에 정답 라벨이 설계상 확정됩니다.

## 준비

```bash
pip install langgraph
```

`.env` 에 `TYPESAFE_API_KEY` 와 `OPENAI_API_KEY` 가 모두 필요합니다.

## 파일

| 파일 | 하는 일 |
|---|---|
| `corpus_tax.py` | 가상 세무 안내 문서 40건 |
| `dataset_tax.py` | 질문 60건 (개발 30 + 검증 30, A·B·C군) |
| `agent_tax.py` | LangGraph 에이전트 (판단 계층 없는 기준선) |
| `retrievers.py` | 낱말 겹침과 문자 3-gram 비교. **모델을 안 부릅니다** |
| `run_eval.py` | 전체 실행 + 2단계 채점 + 답변 게이트 |
| `diagnose.py` | 기권을 원인별로 분해 |

## 평가셋

```text
A군  수록 질문     15+15   문서에 답이 있다      -> 답해야 한다
B군  미수록 질문   10+10   문서에 답이 없다      -> 기권해야 한다
C군  함정 질문      5+5    비슷한 다른 문서가 걸린다
```

각 항목에 **근거 문서 id를 함께 적어뒀습니다.** `diagnose.py` 가 판단 모델 없이
원인을 가를 수 있는 것이 그 덕분입니다.

## 실행 순서

**1. 검색기를 먼저 비교합니다 (모델 호출 없음, 즉시 끝남)**

```bash
python ch13/retrievers.py
```

```text
검색기              개발 recall@3   검증 recall@3       B군 빈결과율
낱말 겹침                 55.0%         55.0%         75.0%
문자 3-gram             90.0%         90.0%         40.0%
```

한국어 조사 때문에 낱말 매칭이 무너집니다. `세금계산서는` 과 `세금계산서` 가
다른 문자열이라서입니다.

**2. 기준선을 잽니다**

```bash
python ch13/run_eval.py
python ch13/diagnose.py ch13_result_word.json
```

**3. 검색을 고치고 다시 잽니다**

```bash
python ch13/run_eval.py --char
```

**4. 답변 게이트를 붙입니다**

```bash
python ch13/run_eval.py --char --gate
```

**5. 위험 영역 정책까지 (선택)**

```bash
python ch13/run_eval.py --char --gate --policy
```

## 책의 실측값

```text
                  coverage           신뢰도          날조
기준선            36.7% / 36.7%    100% / 100%      0 / 0
문자 3-gram       60.0% / 63.3%    100% / 94.7%     0 / 1건
문자 + 게이트     60.0% / 60.0%    100% / 100%      0 / 0
문자 + 게이트 + 정책  56.7% / 56.7%  100% / 100%     0 / 0
                                        (개발셋 / 검증셋, coverage 상한 66.7%)
```

**같은 값이 나오지 않는 것이 정상입니다.** 생성 모델이 바뀌면 답변 문장이 달라지고
채점 결과도 따라 바뀝니다. **자릿수와 방향이 같으면 재현된 것으로 봅니다** —
검색을 고치면 coverage가 오르고, 그때 날조가 따라 나온다는 두 가지가 그 방향입니다.

## 주의할 점 두 가지

**채점기도 측정 대상입니다.** `run_eval.py` 의 채점은 두 단계입니다. 한 번에
세 후보(정답/오답/기권)로 물었더니 기권을 오답으로 분류하는 사고가 났습니다.
원인은 채점기에게 **에이전트가 실제로 본 문서가 아니라 정답 근거 문서**를 준 것이었고,
그러면 "제공된 문서에 없습니다"라는 정직한 기권이 거짓말로 보입니다.

**키워드 정책은 무딥니다.** `--policy` 의 `ALWAYS_REVIEW` 는 위험 영역을 걸러내지만,
"법인 사업자등록에 임대차**계약**서 말고 뭐가 더 필요한가요"가 `계약` 에 걸려
막혔습니다. 계약 위험과 무관한 질문입니다. 여러분의 목록을 만들 때 참고하세요.
